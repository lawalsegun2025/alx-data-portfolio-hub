GitHub Portfolio Guide

A step-by-step guide to publishing your portfolio project professionally on GitHub — even if you've never used it before.

Why GitHub?

GitHub is where data professionals showcase their work. Recruiters, hiring managers, and technical interviewers routinely look at GitHub profiles before interviews. A well-organised, clearly documented project repository tells them more about your capability than a CV ever can.

Step 1: Create a GitHub Account

Go to github.com and create a free account. Use a professional username — ideally your real name or a close variation. This will appear on your portfolio and LinkedIn profile.

Step 2: Create a Repository

Click the + icon and select New repository. Give it a clear, descriptive name using hyphens:

healthcare-analytics-capstone retail-sql-analysis africa-energy-powerbi-dashboard crop-yield-sheets-analysis

Set it to Public, check Add a README file, and click Create.

Step 3: Organise Your Folders

Use a consistent structure for every project. Here is the recommended layout:

your-project-name/ ├── data/ │ ├── raw/ ← original downloaded file (if small enough) │ └── cleaned/ ← your cleaned, analysis-ready file ├── sql/ ← SQL scripts (DA-3 and Capstone projects) ├── scripts/ ← any other scripts ├── dashboard/ ← Power BI .pbix file (DA-4 and Capstone) ├── reports/ ← executive summary, PDF outputs ├── images/ │ └── dashboard.png ← screenshots of key outputs └── README.md

Do not upload datasets larger than ~25MB. For large files, add a note in your README explaining where to download the data (with a direct link).

Step 4: Write a Great README

Your README is the first thing anyone sees. It should answer five questions immediately:

  • What is this project? — One sentence describing the business problem.
  • What did you find? — Two or three specific key findings.
  • What tools did you use? — List the tools and why.
  • Where is the data from? — Name the source and link to it.
  • How do I run or view it? — Brief instructions for opening the files.

A good README structure:

# Project Title ## Business Challenge [One paragraph describing the problem you were solving] ## Key Findings - Finding 1 (specific, evidence-based) - Finding 2 - Finding 3 ## Tools Used - Google Sheets — data cleaning and preparation - MySQL — relational database analysis - Power BI — interactive dashboard ## Dataset Source: [Publisher Name](link) Note: Download the data from the link above and place it in /data/raw/ ## Dashboard Preview ![Dashboard Screenshot](images/dashboard.png) ## How to Use This Repository [Brief instructions] ## Limitations [What the data couldn't tell you] ## Reflections [What you learned and would do differently]

Step 5: Upload Your Files

Drag and drop files into the repository, or use the Add file → Upload files button. Commit each upload with a clear message like "Add cleaned dataset and SQL analysis scripts".

Step 6: Add Screenshots

Always include at least one screenshot of your dashboard or key chart. Upload it to your images/ folder and reference it in your README. A visual preview makes your project significantly more compelling.

Things to Avoid

  • Do not upload files containing personally identifiable information
  • Do not upload datasets where the licence prohibits redistribution
  • Do not upload files larger than 50MB (GitHub limit)
  • Do not leave the README empty or with placeholder text
  • Do not name files final_FINAL_v3_use_this_one.xlsx
